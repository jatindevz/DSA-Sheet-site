<h2 id="pattern-1-sliding-window">Pattern 1: Sliding Window</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Sliding window is one of the most frequently tested patterns in interviews. It optimizes brute force O(n²) solutions to O(n) by maintaining a window of elements and sliding it across the array/string. This pattern appears in substring problems, subarray problems, and anywhere you need to track a contiguous sequence.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Finding longest/shortest substring with condition</li>
<li>Subarray with target sum/property</li>
<li>Maximum/minimum in subarrays of size K</li>
<li>Problems with "contiguous" elements</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>Fixed window: Move right, slide left when window size exceeds K</li>
<li>Variable window: Expand right, shrink left when condition violated</li>
</ul>

<h2 id="pattern-3-two-pointers">Pattern 3: Two Pointers</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Two pointers is your go-to technique for array/string problems that require comparing or processing elements from different positions. It reduces time complexity from O(n²) to O(n) in many cases. This is one of the most versatile patterns - works on sorted arrays, palindromes, and partitioning problems.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Sorted array problems</li>
<li>Palindrome checking</li>
<li>Pair/triplet sum problems</li>
<li>Removing duplicates</li>
<li>Partitioning arrays</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>Opposite direction: Start from both ends, move toward center</li>
<li>Same direction: Both pointers move forward at different speeds</li>
</ul>

<h2 id="pattern-4-fast--slow-pointers">Pattern 4: Fast &amp; Slow Pointers</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Fast and slow pointers (tortoise and hare) is an elegant technique for detecting cycles and finding middle elements in linked lists. It uses O(1) space where naive approaches need O(n). This pattern is a favorite in interviews because it tests your understanding of pointer manipulation.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Cycle detection in linked lists</li>
<li>Finding middle of linked list</li>
<li>Finding cycle start point</li>
<li>Happy number problems</li>
<li>Palindrome linked list</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>Slow moves 1 step, fast moves 2 steps</li>
<li>If cycle exists, they'll meet</li>
<li>After meeting, reset one to head to find cycle start</li>
</ul>

<h2 id="pattern-6-monotonic-stack">Pattern 6: Monotonic Stack</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Monotonic stack maintains elements in increasing or decreasing order, allowing you to find next/previous greater/smaller elements efficiently. This pattern transforms O(n²) brute force solutions into O(n). It's particularly elegant once you understand when to push and when to pop.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Next greater/smaller element</li>
<li>Previous greater/smaller element</li>
<li>Histogram problems</li>
<li>Temperature problems</li>
<li>Stock span problems</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>Increasing stack: Pop when current &gt; stack.top()</li>
<li>Decreasing stack: Pop when current &lt; stack.top()</li>
<li>Store indices rather than values for more info</li>
</ul>

<h2 id="pattern-7-top-k-elements">Pattern 7: Top K Elements</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Finding top K elements is extremely common in real-world applications and interviews. Using a heap of size K gives O(n log k) complexity, which is much better than sorting O(n log n) when K is small. This pattern appears in recommendation systems, analytics, and optimization problems.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>K largest/smallest elements</li>
<li>K most frequent elements</li>
<li>K closest points</li>
<li>Median finding</li>
<li>Merging K sorted lists</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>K largest → Use min heap of size K</li>
<li>K smallest → Use max heap of size K</li>
<li>Maintain heap size = K, replace root if better element found</li>
</ul>

<h2 id="pattern-9-modified-binary-search">Pattern 9: Modified Binary Search</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Binary search isn't just for finding elements in sorted arrays. Modified binary search applies the same principle to rotated arrays, search space reduction, and optimization problems. Recognizing when a problem can use binary search on the "answer space" is a key skill.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Rotated sorted arrays</li>
<li>Peak finding</li>
<li>Search in 2D matrix</li>
<li>Finding square root</li>
<li>Capacity optimization problems</li>
<li>"Minimum/maximum value such that..."</li>
</ul>

<h2 id="pattern-10-binary-tree-traversal">Pattern 10: Binary Tree Traversal</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Tree traversal is fundamental to all tree problems. Understanding the three main traversals (inorder, preorder, postorder) and level-order traversal is essential. Each traversal has specific use cases - inorder for BST, preorder for copying, postorder for deletion, level-order for shortest path.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Process all nodes in specific order</li>
<li>Inorder: BST sorted order, validation</li>
<li>Preorder: Tree serialization, copying</li>
<li>Postorder: Tree deletion, dependency resolution</li>
<li>Level-order: Shortest path, level-wise processing</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>DFS: Recursion or stack (inorder, preorder, postorder)</li>
<li>BFS: Queue (level-order)</li>
</ul>

<h2 id="pattern-11-depth-first-search-dfs">Pattern 11: Depth-First Search (DFS)</h2>
<p><strong>Why This Pattern Matters:</strong><br>
DFS explores as deep as possible before backtracking. It's your go-to for tree problems, graph cycle detection, path finding, and exploring all possibilities. DFS is particularly elegant with recursion and forms the basis for backtracking problems.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Tree depth/height problems</li>
<li>Path sum problems</li>
<li>Cycle detection</li>
<li>Connected components</li>
<li>Topological sort</li>
<li>Graph coloring</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>Mark visited</li>
<li>Process current node</li>
<li>Recursively visit neighbors</li>
<li>Unmark if backtracking needed</li>
</ul>

<h2 id="pattern-12-breadth-first-search-bfs">Pattern 12: Breadth-First Search (BFS)</h2>
<p><strong>Why This Pattern Matters:</strong><br>
BFS explores level by level, guaranteeing shortest path in unweighted graphs. It's essential for level-order problems, shortest path problems, and minimum step problems. The queue-based implementation is intuitive and appears in many real-world scenarios like social networks and maze solving.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Shortest path in unweighted graph</li>
<li>Level-order traversal</li>
<li>Minimum steps/moves problems</li>
<li>Connected components</li>
<li>"Nearest" problems</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>Use queue</li>
<li>Add start node(s)</li>
<li>Process level by level</li>
<li>Track visited to avoid cycles</li>
</ul>

<h2 id="pattern-13-matrix-traversal">Pattern 13: Matrix Traversal</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Matrix problems are just graph problems in disguise - each cell is a node, and adjacent cells are neighbors. Once you see this connection, grid problems become straightforward graph traversal. This pattern is extremely common in interviews and tests your ability to handle 2D arrays and boundary conditions.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Island problems</li>
<li>Flood fill</li>
<li>Path finding in grid</li>
<li>Region identification</li>
<li>Any 2D grid problem</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ul>
<li>Treat as graph with 4 or 8 neighbors</li>
<li>DFS or BFS from each unvisited cell</li>
<li>Watch for boundaries</li>
</ul>

<h2 id="pattern-14-backtracking">Pattern 14: Backtracking</h2>
<p><strong>Why This Pattern Matters:</strong><br>
Backtracking explores all possible solutions by making choices, exploring consequences, and undoing choices if they don't work. It's essential for permutations, combinations, subsets, and constraint satisfaction problems. While potentially exponential, it's often the only way to solve certain problems.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Generate all permutations/combinations</li>
<li>Subset problems</li>
<li>Sudoku, N-Queens</li>
<li>String partitioning</li>
<li>Path finding with constraints</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ol>
<li data-length="1">Make a choice</li>
<li data-length="1">Explore with that choice (recurse)</li>
<li data-length="1">Undo the choice (backtrack)</li>
<li data-length="1">Try next choice</li>
</ol>

<h2 id="pattern-15-dynamic-programming">Pattern 15: Dynamic Programming</h2>
<p><strong>Why This Pattern Matters:</strong><br>
DP is the most feared but most rewarding pattern. It optimizes recursive solutions by storing results of subproblems. While there are many DP patterns (1D, 2D, LIS, LCS, knapsack), the key is recognizing overlapping subproblems and optimal substructure. Master the mindset, not just individual problems.</p>
<p><strong>When to Use:</strong></p>
<ul>
<li>Optimization problems (max/min)</li>
<li>Counting problems</li>
<li>Decision making problems</li>
<li>Problems with overlapping subproblems</li>
<li>Keywords: "maximum", "minimum", "longest", "count ways"</li>
</ul>
<p><strong>Key Technique:</strong></p>
<ol>
<li data-length="1">Identify state variables</li>
<li data-length="1">Write recurrence relation</li>
<li data-length="1">Identify base cases</li>
<li data-length="1">Memoize or build bottom-up</li>
</ol>
